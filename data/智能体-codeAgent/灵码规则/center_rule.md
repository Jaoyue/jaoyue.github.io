## 一、核心开发原则

- 严格遵循 **SOLID、DRY、KISS、YAGNI** 原则
- 遵循 **OWASP 安全最佳实践**（如输入验证、SQL注入防护、XSS防护等）
- 采用 **分层架构设计**，确保职责分离

---

## 二、代码风格规范

1. **命名规范**：
   - **类名**：`UpperCamelCase` 风格，但以下情形例外：`DO` / `BO` / `DTO` / `VO` / `AO` / `PO` / `UID` 等。（如 `UserServiceImpl` / `UserDO`）
   - **方法名 / 参数名 / 成员变量 / 局部变量**：`lowerCamelCase`风格，（如 `saveUser` / `getHttpMessage()` / `inputUserId`）
   - **常量**：`UPPER_SNAKE_CASE`（如 `MAX_LOGIN_ATTEMPTS`）
   - **严禁魔法值**：所有未定义的数值、字符串字面量必须提取为常量或枚举
2. **注释规范**：
   - **类级注释**：所有类必须添加 Javadoc 注释，说明类的职责和主要功能
      - **方法级注释**：所有方法必须添加详细的 Javadoc 注释，包括：
         - 方法功能详细描述
         - `@param` 参数说明
         - `@return` 返回值说明
         - `@throws` 异常说明（如有）
      - **复杂逻辑注释**：对于复杂的业务逻辑、算法或特殊处理，必须添加行内注释说明
      - **TODO/FIXME 标记**：
         - 计划待完成的任务需要添加 `// TODO: 具体说明` 标记
         - 存在潜在缺陷的逻辑需要添加 `// FIXME: 问题描述` 标记
      - **禁止**：避免无意义的注释，代码即文档，优先通过清晰的命名和结构表达意图
3. **代码格式化**：
   - 使用 IntelliJ IDEA 默认的 Spring Boot 风格
   - 禁止手动修改代码缩进（依赖 IDE 自动格式化）

## 三、安全与性能规范

1. **输入校验**：
   - 禁止直接拼接 SQL 防止注入攻击
   - SQL 注入：使用 #{}，禁止 ${}（除非白名单校验）
2. **事务管理**：
   - `@Transactional` 注解仅标注在 Service 方法上
   - `@Transactional` 必须指定事务的回滚异常类型，建议使用 @Transactional(rollbackFor = Exception.class)
   - 避免在循环中频繁提交事务
3. **性能优化**：
   - 避免在循环中执行数据库查询（批量操作优先）或远程 RPC 接口

## 四、扩展性设计规范

1. **日志规范**：
   - 使用 `SLF4J` 记录日志（禁止直接使用 `System.out.println`）
      - **日志级别使用**：
         - `INFO`：关键业务流程节点、重要操作记录
         - `WARN`：潜在问题、不符合预期但不影响功能的情况
         - `ERROR`：错误信息，必须记录异常堆栈
      - **日志格式**：使用结构化日志，包含 traceId 等关键信息
      - 禁止在日志消息中打印敏感信息（如密码、Token、身份证号等）
      - 日志输出必须使用占位符（`log.info("用户{}登录", userId)`），禁止字符串拼接
      - 避免在高频调用的方法中打印过多日志，影响性能
