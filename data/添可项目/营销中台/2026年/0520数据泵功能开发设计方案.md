## 二、需求拆解

| 需求项           | 说明                                                         |
| ---------------- | ------------------------------------------------------------ |
| **指令类型扩展** | `is_single` 新增一种类型：**4-数据泵**                       |
| **数据来源**     | 通过 `from_data_source_text` 配置查询SQL                     |
| **数据去向**     | 通过 `to_data_source_id` 配置目标数据源，`to_data_source_table` 配置JSON（含目标表名+前置SQL） |
| **执行逻辑**     | 解析JSON → 如有前置SQL则在目标库执行 → 分页查询源数据 → 批量插入目标表，所有操作在同一事务中 |
| **分页大小**     | 分页查询 5000 条/页，批量插入按 1000 条/批提交              |

## 三、数据库变更

### 3.1 `task_instruction` 表（无需DDL变更，复用现有字段）

| 字段                    | 数据泵中的语义                                              |
| ----------------------- | ----------------------------------------------------------- |
| `from_data_source_id`   | 源数据库配置ID                                              |
| `from_data_source_text` | 源端查询SQL（如 `SELECT id, name, status FROM source_table`） |
| `to_data_source_id`     | 目标数据库配置ID                                            |
| `to_data_source_table`  | **JSON配置**（含目标表名+前置SQL）                          |
| `is_single`             | **4=数据泵**                                                |

> `to_data_source_table` JSON 示例：
> ```json
> {
>   "targetTable": "dmp.store_info",
>   "preSql": "DELETE FROM dmp.store_info WHERE create_date < DATE_SUB(NOW(), INTERVAL 30 DAY)"
> }
> ```
>
> - `targetTable`：目标表名，支持带库名前缀（如 `dmp.store_info`）
> - `preSql`：前置SQL，可选。不为空时，在开启事务后先执行该SQL（一般用于删除历史数据）

```java
package com.tineco.dbu.monitor.enums;

import lombok.Getter;

/**
 * 指令类型枚举
 */
@Getter
public enum InstructionTypeEnum {

    SINGLE(1, "单指令"),
    HEALTH_CHECK(2, "健康检查"),
    CROSS_DB_MATCH(3, "跨库匹配查询"),
    DATA_PUMP(4, "数据泵");

    private final Integer code;
    private final String desc;

    InstructionTypeEnum(Integer code, String desc) {
        this.code = code;
        this.desc = desc;
    }

    public static String getDescByCode(Integer code) {
        for (InstructionTypeEnum type : values()) {
            if (type.code.equals(code)) {
                return type.desc;
            }
        }
        return "未知";
    }
}
```

### 4.3 数据泵执行器设计

#### 4.3.1 数据泵执行流程

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  获取源/目标连接 │ --> │  解析JSON配置    │ --> │  COUNT查询总条数 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                                                        │
                              ┌─────────────────────────┘
                              ▼
                       ┌─────────────────┐
                       │  开启目标库事务  │
                       └─────────────────┘
                              │
                    ┌─────────┴─────────┐
                    ▼                   ▼
            ┌──────────────┐    ┌──────────────┐
            │  preSql有值？ │    │  分页查询源数据│
            │  是 → 执行preSql│    │  (LIMIT/OFFSET)│
            └──────────────┘    └──────────────┘
                                         │
                                         ▼
                                  ┌──────────────┐
                                  │ 批量插入目标库│
                                  │ (同事务内)   │
                                  └──────────────┘
                                         │
                              ┌──────────┴──────────┐
                              ▼                     ▼
                       ┌──────────────┐      ┌──────────────┐
                       │  还有下一页？  │      │  提交事务    │
                       │  是 → 继续查询 │      │  返回摘要    │
                       └──────────────┘      └──────────────┘
```

> **执行说明**：
> 1. `to_data_source_table` 解析为 `DataPumpConfig`，获取 `targetTable` 和 `preSql`
> 2. 先 COUNT 源表总条数
> 3. 开启目标库事务
> 4. 如 `preSql` 不为空，在事务内先执行前置SQL（如删除历史数据）
> 5. 分页查询源数据（每页 5000 条），每页查完后在同一事务中批量插入目标表（每批 1000 条）
> 6. 所有操作（preSql + 全部插入）共享同一个目标库事务，要么全部成功提交，要么全部回滚

### 4.5 关键实现代码

#### 4.5.1 `DataPumpServiceImpl`

```java
package com.tineco.dbu.monitor.service.impl;

import com.alibaba.fastjson.JSON;
import com.tineco.dbu.monitor.entity.dto.DataPumpConfig;
import com.tineco.dbu.monitor.entity.po.TaskInstruction;
import com.tineco.dbu.monitor.service.IDataPumpService;
import com.tineco.dbu.monitor.service.IDatabaseConfigService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.apache.commons.collections4.CollectionUtils;
import org.apache.commons.lang3.StringUtils;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.DataSourceTransactionManager;
import org.springframework.stereotype.Service;
import org.springframework.transaction.TransactionStatus;
import org.springframework.transaction.support.DefaultTransactionDefinition;

import java.util.*;
import java.util.stream.Collectors;

@Service
@Slf4j
@RequiredArgsConstructor
public class DataPumpServiceImpl implements IDataPumpService {

    private final IDatabaseConfigService databaseConfigService;

    private static final int PAGE_SIZE = 5000;

    @Override
    public List<Map<String, Object>> execute(TaskInstruction instruction) {
        // 1. 获取源和目标 JdbcTemplate
        JdbcTemplate fromTemplate = databaseConfigService.getJdbcTemplateById(instruction.getFromDataSourceId());
        JdbcTemplate toTemplate = databaseConfigService.getJdbcTemplateById(instruction.getToDataSourceId());

        // 2. 解析JSON配置
        DataPumpConfig config = parseConfig(instruction);
        String targetTable = config.getTargetTable();

        // 3. 查询源表总条数
        String originalSql = instruction.getFromDataSourceText();
        String countSql = "SELECT COUNT(*) FROM (" + originalSql + ") AS pump_count";
        Integer totalCount = fromTemplate.queryForObject(countSql, Integer.class);
        if (totalCount == null || totalCount == 0) {
            Map<String, Object> summary = new HashMap<>();
            summary.put("操作类型", "数据泵");
            summary.put("源数据行数", 0);
            summary.put("插入行数", 0);
            summary.put("目标表", targetTable);
            return Collections.singletonList(summary);
        }

        // 4. 先查第一页，提取列名（后续复用列名）
        String firstPageSql = originalSql + " LIMIT " + PAGE_SIZE + " OFFSET 0";
        List<Map<String, Object>> firstPage = fromTemplate.queryForList(firstPageSql);
        if (CollectionUtils.isEmpty(firstPage)) {
            Map<String, Object> summary = new HashMap<>();
            summary.put("操作类型", "数据泵");
            summary.put("源数据行数", 0);
            summary.put("插入行数", 0);
            summary.put("目标表", targetTable);
            return Collections.singletonList(summary);
        }

        Set<String> columns = firstPage.get(0).keySet();
        String insertSql = buildInsertSql(targetTable, columns);

        // 5. 开启目标库事务
        DataSourceTransactionManager txManager = databaseConfigService.getTransactionManagerById(instruction.getToDataSourceId());
        DefaultTransactionDefinition def = new DefaultTransactionDefinition();
        TransactionStatus status = txManager.getTransaction(def);

        int totalInserted = 0;
        try {
            // 5.1 执行前置SQL（如删除历史数据）
            if (StringUtils.isNotBlank(config.getPreSql())) {
                log.info("数据泵执行前置SQL: {}", config.getPreSql());
                toTemplate.execute(config.getPreSql());
            }

            // 5.2 插入第一页
            totalInserted += doBatchInsert(toTemplate, insertSql, columns, firstPage);

            // 5.3 分页循环查询剩余页
            for (int offset = PAGE_SIZE; offset < totalCount; offset += PAGE_SIZE) {
                String pageSql = originalSql + " LIMIT " + PAGE_SIZE + " OFFSET " + offset;
                List<Map<String, Object>> pageData = fromTemplate.queryForList(pageSql);
                if (CollectionUtils.isEmpty(pageData)) {
                    break;
                }
                totalInserted += doBatchInsert(toTemplate, insertSql, columns, pageData);
            }

            // 提交事务
            txManager.commit(status);
        } catch (Exception e) {
            txManager.rollback(status);
            throw new RuntimeException("数据泵执行失败，已回滚目标库事务: " + e.getMessage(), e);
        }

        // 6. 返回摘要
        Map<String, Object> summary = new HashMap<>();
        summary.put("操作类型", "数据泵");
        summary.put("源数据行数", totalCount);
        summary.put("插入行数", totalInserted);
        summary.put("目标表", targetTable);
        return Collections.singletonList(summary);
    }

    /**
     * 解析数据泵配置JSON
     */
    private DataPumpConfig parseConfig(TaskInstruction instruction) {
        String configJson = instruction.getToDataSourceTable();
        if (configJson == null || configJson.trim().isEmpty()) {
            throw new RuntimeException("数据泵配置不能为空，请在 to_data_source_table 字段配置JSON");
        }
        try {
            DataPumpConfig config = JSON.parseObject(configJson, DataPumpConfig.class);
            if (config.getTargetTable() == null || config.getTargetTable().trim().isEmpty()) {
                throw new RuntimeException("数据泵配置缺少 targetTable 字段");
            }
            return config;
        } catch (Exception e) {
            log.error("数据泵配置JSON解析失败: {}", configJson, e);
            throw new RuntimeException("数据泵配置JSON解析失败: " + e.getMessage());
        }
    }

    /**
     * 构建 INSERT SQL（复用）
     */
    private String buildInsertSql(String tableName, Set<String> columns) {
        String columnStr = String.join(", ", columns);
        String placeholder = columns.stream().map(c -> "?").collect(Collectors.joining(", "));
        return String.format("INSERT INTO %s (%s) VALUES (%s)", tableName, columnStr, placeholder);
    }

    /**
     * 批量插入一页数据
     */
    private int doBatchInsert(JdbcTemplate template, String sql, Set<String> columns,
                              List<Map<String, Object>> dataList) {
        int batchSize = 1000;
        List<Object[]> batchArgs = new ArrayList<>();
        int inserted = 0;

        for (Map<String, Object> row : dataList) {
            Object[] args = columns.stream().map(row::get).toArray();
            batchArgs.add(args);

            if (batchArgs.size() >= batchSize) {
                template.batchUpdate(sql, batchArgs);
                inserted += batchArgs.size();
                batchArgs.clear();
            }
        }

        if (!batchArgs.isEmpty()) {
            template.batchUpdate(sql, batchArgs);
            inserted += batchArgs.size();
        }

        return inserted;
    }
}
```

## 七、风险与注意事项

| 风险点                 | 应对措施                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **目标表结构不一致**   | 确保查询SQL的字段名与目标表的列名一致，否则插入会报错        |
| **大批量数据内存溢出** | 分页查询 5000 条/页，批量插入 1000 条/批，避免一次性加载全部数据 |
| **事务过大**           | preSql + 全部分页插入在同一事务中，数据量极大时注意数据库事务日志容量 |
| **SQL注入风险**        | `targetTable` 做正则校验，只允许 `[a-zA-Z0-9_.]`（支持库名前缀的点号） |
| **JSON解析异常**       | 前端需校验JSON格式，后端解析失败时抛出明确错误信息            |
| **并发执行冲突**       | 同一指令的数据泵任务建议配置为单机执行，避免多节点同时写入   |
