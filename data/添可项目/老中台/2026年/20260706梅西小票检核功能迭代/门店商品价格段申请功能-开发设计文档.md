### 2.2 索引设计说明

| 索引 | 用途 |
|------|------|
| `idx_store_segment_code` | 申请单号模糊查询 + 精确匹配 |
| `idx_audit_status` | 按审批状态筛选申请单 |
| `idx_creation_date` | 按创建时间范围查询 + 排序 |
| `idx_product_line_id` | **核心查询**：按商品行ID查找关联门店（审批后生成明细用） |
| `idx_product_store` | 明细表通用组合查询：产品 + 门店 |

#### 8.2.7 validateSubmit 提交校验

```java
private void validateSubmit(ImsProductPriceStoreSegmentHeader header) {
    // 1. 检查商品行
    List<ImsProductPriceStoreSegmentProductLine> productList =
        productLineService.findByProperty("store_segment_header_id",
            header.getStoreSegmentHeaderId());
    if (productList.isEmpty()) {
        throw new BaseRuntimeException("存在商品行为空，不允许提交");
    }

    // 2. 检查门店行
    List<ImsProductPriceStoreSegmentStoreLine> storeList =
        storeLineService.findByProperty("store_segment_header_id",
            header.getStoreSegmentHeaderId());
    if (storeList.isEmpty()) {
        throw new BaseRuntimeException("存在门店行为空，不允许提交");
    }

    // 3. 校验价格合理性：price_min <= price_max
    for (ImsProductPriceStoreSegmentProductLine line : productList) {
        if (line.getPriceMin() != null && line.getPriceMax() != null
                && line.getPriceMin().compareTo(line.getPriceMax()) > 0) {
            throw new BaseRuntimeException(
                "产品[" + line.getProductSapId() + "]价格下限不得大于价格上限");
        }
    }

    // 4. 时间段唯一性校验：同一产品+门店在重叠时间段不能有审批中单据
    QueryImsProductPriceStoreSegmentHeader query = new QueryImsProductPriceStoreSegmentHeader();
    query.setStartDate(header.getStartDate());
    query.setEndDate(header.getEndDate());
    query.setProductSapIdList(productList.stream()
        .map(ImsProductPriceStoreSegmentProductLine::getProductSapId)
        .collect(Collectors.toList()));
    query.setStoreCodeList(storeList.stream()
        .map(ImsProductPriceStoreSegmentStoreLine::getStoreCode)
        .collect(Collectors.toList()));

    List<ImsProductPriceStoreSegmentHeaderVo> conflictList = mapper.findBySubmit(query);
    if (!conflictList.isEmpty()) {
        throw new BaseRuntimeException("存在相同时间范围内的审批中单据，不允许提交");
    }
}
```

## 10. 关键注意事项

### 10.1 审批流配置

**BPM 流程定义 Key**：需要在 BPM 管理平台创建一个新的流程定义，Key 建议为 `"STORE_PRICE_SEGMENT"`（由前端传入 `processDefinitionKey` 字段）。

**回调地址**：`POST /imsProductPriceStoreSegmentHeader/updateStatus`（`ActBpmProcessCallbackBo` 会自动携带审批结果）。

**BPM 必须字段**（在 `HeaderBo` 和 `DeleteBo` 中带 `@NotNull`）：
| 字段 | 来源 | 说明 |
|------|------|------|
| `processDefinitionKey` | 前端传入 | BPM流程定义Key |
| `orgId` | 前端传入 | 所属OU组织 |
| `responsibilityId` | 前端传入 | 职责ID |
| `departmentId` | 前端传入 | 部门ID（可选） |
| `positionId` | 前端传入 | 职位ID（可选） |

### 10.2 BPM 回调接口的安全注意

`updateStatus` 接口仅接受 BPM 引擎的回调，应**不加用户认证拦截**（参照现有实现）。Controller 中不调用 `super.validatorData(result)`，直接接受 `ActBpmProcessCallbackBo`。

### 10.3 事务与锁

| 方法 | 事务注解 | 说明 |
|------|---------|------|
| `saveOrUpdate` | `@GlobalTransactional` + `@Transactional` | 分布式事务：BPM调用可能跨服务 |
| `saveOrUpdateAll` | `@Transactional` | 仅本地事务，不包含BPM调用 |
| `updateStatusById` | `@Transactional` | 本地事务：更新头表+生成明细 |
| `deleteAll` | `@Transactional` | 本地事务：有BPM调用但仅在非DRAFT时触发 |
| `batchDelete` | `@Transactional` | 简单批量删除 |

> **注意**：`saveOrUpdateAll` 调用 `saveOrUpdate`（后者已有 `@GlobalTransactional`），所以 `saveOrUpdateAll` 自己的 `@Transactional` 会参与到外层 `@GlobalTransactional` 中，不会重复。

### 10.4 流水号编码规则配置

需要在流水号管理平台配置 BizKey：`"IMSSTOREPRICESEGMENT"`，格式建议：`PSA-yyyyMMdd-序号`（如 PSA-20260708-0001）。

### 10.5 审批状态码值字典

使用已有字典 `"imsProductAuditStatus"`（与促销价目表一致），建议在数据字典中新增状态码：
- `DRAFT` — 草稿
- `APPROVAL` — 待审批
- `ALLOW` — 已审批
- `REJECT` — 已驳回

### 10.6 数据聚合/转义

| VO字段 | 注解 | 说明 |
|--------|------|------|
| `auditStatus` | `@SieEscapeField(BASE_LOOK_UP, "imsProductAuditStatus")` | 审批状态码值转义 |
| `createdBy` | `@SieEscapeField(BASE_USER_ID)` | 用户ID→用户名 |
| `storeCode` | `@SieDataAggregate(MDM_BASE_CUSTOMER)` | 门店主数据聚合（门店名称、零售业态等） |
| `productSapId` | `@SieDataAggregate(MDM_BASE_PRODUCT)` | 产品主数据聚合（产品名称、大类等） |

### 10.7 前端联调注意

1. **saveAll 接口的数据结构**：商品行内嵌门店行 `storeLines`，后端按此嵌套结构平铺保存
2. **审批状态不可编辑**：`APPROVAL` 和 `ALLOW` 状态的申请单，前端应禁用编辑和删除按钮
3. **SAP ID 自动带出**：前端输入 SAP ID 后失焦调用产品查询接口自动带出名称、大类等信息（后端也做校验）
4. **门店编码自动带出**：同理，调用主数据查询接口自动带出

### 10.8 性能注意事项

1. **分页大小**：默认 `ImsProductConstants.PAGE_SIZE = 1000`，但导出时应放开限制
2. **笛卡尔积规模**：如果商品×门店组合过多（如 100商品 × 500门店 = 50000条），审批回调的 `generateSegmentPrices` 会批量插入大量数据，建议使用 `saveBatch` 分批处理
3. **索引覆盖**：明细表 `idx_date_range` 和 `idx_product_store` 组合索引确保查询性能
