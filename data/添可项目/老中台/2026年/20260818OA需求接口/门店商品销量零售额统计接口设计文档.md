# 门店商品销量 / 零售额统计接口 —— 开发设计文档

## 1. 需求概述
在 `SieApiController` 新增一个供 外部系统 调用的接口，从 `sp_store_product_stat`（门店商品统计表）按条件查询销量与零售额，并按三个维度返回：

1. **维度一**：所传入的**全部门店**，按每个 SKU 汇总「销量合计 + 零售额合计」。
2. **维度二**：取**第一个门店**所属分部（`sales_region`），返回该分部下**每个 SKU**的「销量合计 + 零售额合计」。
3. **维度三**：同样取第一个门店所属分部，返回该分部的**整体「销量合计 + 零售额合计」**（不按 SKU 拆分）。

## 2. 接口定义

| 项 | 内容 |
| --- | --- |
| 请求方式 | `POST` |
| 访问路径 | `/api/api-store/queryStoreProductStat` |
| 请求格式 | `application/json`（@RequestBody） |
| 返回结构 | `Result.success(data)`，data 见下方「出参」 |

### 入参（`StoreProductStatQueryDTO`）
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `storeNos` | `List<String>` | 是 | 门店编码，支持多个 |
| `materialNos` | `List<String>` | 是 | 物料编码，支持多个 |
| `startDate` | `String` | 是 | 开始时间，格式 `yyyy-MM-dd` |
| `endDate` | `String` | 是 | 结束时间，格式 `yyyy-MM-dd` |

> 校验规则（在 Controller 层）：`startDate`、`endDate`、`storeNos`、`materialNos` 任一为空即返回 `Result.error("xxx不能为空！")`。

### 出参（data 结构）
```json
{
  "storeSkuStatList": [
    { "materialNo": "110-1711-0001", "salesCount": 120, "salesAmount": 35988.00 }
  ],
  "salesRegionCode": "EAST",
  "salesRegionName": "华东分部",
  "regionSkuStatList": [
    { "materialNo": "110-1711-0001", "salesCount": 980, "salesAmount": 294000.00 }
  ],
  "regionTotal": { "salesCount": 980, "salesAmount": 294000.00 }
}
```
- `storeSkuStatList`：维度一（全部门店按 SKU）。
- `salesRegionCode`：第一个门店的 `sales_region`（分部编码，原样返回）。
- `salesRegionName`：`salesRegionCode` 对应的中文名，通过 `BizDictionaryCacheManager.getBusinessDictionaryValue(BizDictionaryType.DISTRIBUTOR_SALE_AREA, code)` 从缓存获取；取不到时返回空字符串。
- `regionSkuStatList`：维度二（分部按 SKU）。分部无门店时为空数组。
- `regionTotal`：维度三（分部整体汇总）。分部无门店时为 0/0.0。

## 3. 涉及的数据表

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `sp_store_product_stat` | 门店商品统计（销量/零售额数据源） | `store_id`(Long)、`material_no`(String)、`stat_time`(Long 时间戳)、`sales_count`(Integer)、`sales_amount`(Double) |
| `sp_store_info` | 门店主表 | `id`(=store_id)、`store_no`、`sales_region`(分部) |

> 说明：`sp_store_product_stat` 以 `store_id`（门店主键）关联门店，而接口入参是 `storeNo`（门店编码），因此需先在 `sp_store_info` 中把 `storeNo` 映射为 `store_id`。

## 4. SQL 设计（原生 SQL，沿用项目 `findFieldsWithFullSql` 范式）

约定：`stat_time` 用时间戳比较，`startDate/endDate` 经 `DateUtil.getStartTimeOfDateStr / getEndTimeOfDateStr` 转换为 `yyyy-MM-dd` 当天 00:00 与 23:59:59。

**维度一 / 维度二（按 SKU 汇总，仅 `store_id in (...)` 不同）：**
```sql
select material_no,
       sum(sales_count)  as salesCount,
       sum(sales_amount) as salesAmount
from sp_store_product_stat
where store_id in ( <门店ID列表> )
  and material_no in ( '<物料编码1>', '<物料编码2>' )
  and stat_time >= <开始时间戳>
  and stat_time <= <结束时间戳>
group by material_no;
```

**维度三（分部整体汇总）：**
```sql
select sum(sales_count)  as salesCount,
       sum(sales_amount) as salesAmount
from sp_store_product_stat
where store_id in ( <分部下门店ID列表> )
  and material_no in ( '<物料编码>' )
  and stat_time >= <开始时间戳>
  and stat_time <= <结束时间戳>;
```

- 维度一 `store_id in (...)` 取「入参门店映射后的 id」。
- 维度二 / 三 `store_id in (...)` 取「第一个门店 `sales_region` 下所有门店的 id」（通过 `sp_store_info.sales_region` 查询）。

## 5. 实现要点 / 关键决策

1. **门店编码 → 门店ID**：`SpStoreInfoDao.findByStoreNoIn(storeNos)` 拿到 `SpStoreInfo` 列表，再取其 `id` 作为 `store_id` 集合（与现有 `getStoreProduct` 逻辑一致）。
2. **取第一个门店分部**：`storeInfos.get(0).getSalesRegion()`（直接取 `sp_store_info.sales_region`，为分部编码）。
3. **分部门店集合**：`SpStoreInfoDao.findBySalesRegion(salesRegion)` → ids。若该分部无门店，直接返回空/0，避免生成 `in ()` 非法 SQL。
4. **分部中文名**：`salesRegionCode` 为原始编码；`salesRegionName` 用 `BizDictionaryCacheManager.getBusinessDictionaryValue(BizDictionaryType.DISTRIBUTOR_SALE_AREA, code)` 取中文（与项目既有 `SpStoreInfoServiceImpl` 口径一致），编码为空或字典未命中时返回空字符串。
4. **聚合方式**：直接原生 SQL `sum + group by`，使用 `SqlParamUtil.getInteger / getDouble0` 安全提取结果，避免逐行 Java 聚合。
5. **SQL 注入防护**：`materialNos` 为字符串，拼接到 `in (...)` 前校验其仅含 `[A-Za-z0-9_-]`，拒绝非法字符。
6. **服务端时间处理**：与项目现有 `getStoreProduct` 保持一致，使用 `DateUtil.DEFAULT` 格式。
