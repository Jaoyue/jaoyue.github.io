# 值班日历功能开发设计文档

## 1. 概述

### 1.1 背景
为 `hinton-agent-mario-server` 项目新增一个值班日历模块，用于维护和管理日常值班安排。功能覆盖事项管理、值班地点管理、值班安排（日历视图）、值班导入/导出等。

### 1.2 范围
- 后端：新增数据库表、RESTful 接口、业务逻辑实现。
- 前端：新增值班日历页面、事项弹窗、值班弹窗、导入弹窗。

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 事项 | 值班所属的类别/主题，如"全部事项值班安排"，具有时间范围。 |
| 值班 | 某一天某个时间段内，指定部门/人员在指定地点执行的具体值班记录。 |
| 班次类型 | 现场值班（site）/ 远程值班（remote）。 |
| 值班地点 | 固定字典（详见 `DutyLocationEnum`），不再单独维护地点表，常见值：四期（PHASE_4）/ 六期（PHASE_6）/ 七期（PHASE_7）/ 老厂（OLD_FACTORY）。 |

## 3. 需求描述

### 3.1 功能清单

| 序号 | 功能 | 说明 |
|------|------|------|
| 1 | 事项管理 | 新增/查看/编辑/删除值班事项；事项包含名称、开始日期、结束日期。 |
| 2 | 值班地点字典 | 值班地点为固定字典（`DutyLocationEnum`），通过 `GET /duty/location/list` 获取下拉，无需维护地点表。 |
| 3 | 值班日历 | 按月展示值班安排；支持按事项、月份筛选；可点击日期查看/编辑当天值班。 |
| 4 | 新增值班 | 弹窗表单：事项、值班日期、时间段、班次类型、值班地点、值班部门、值班人员。 |
| 5 | 编辑值班 | 仅创建人可编辑已保存的值班记录。 |
| 6 | 导入值班 | 支持 CSV 导入：事项、日期、开始时间、结束时间、班次类型、地点、部门、人员。 |
| 7 | 导出值班 | 支持导出当前筛选条件下的值班数据。 |

### 3.2 UI 说明

#### 3.2.1 值班日历主界面
- 顶部查询区：事项名称（下拉选择）、月份选择（如 `2026-08`）、查询/重置按钮。
- 操作区：新增事项、新增值班、导入值班、导出值班按钮。
- 统计区：显示"全部事项值班安排 共 X 条值班记录"。
- 日历区：按月展示，左侧/顶部显示星期；每天卡片展示值班条目。
- 图例：现场值班（site）蓝色、远程值班（remote）紫色。
- 提示：点击日期网格新增，点击值班条目编辑。

#### 3.2.2 新增事项弹窗
- 事项名称（必填，最多 30 字）
- 时间范围：开始日期 至 结束日期（必填）
- 按钮：取消、确认

#### 3.2.3 新增值班弹窗
- 事项选择（必填，下拉）
- 值班日期（必填，日期选择）
- 时间段：开始时间 至 结束时间（必填，如 09:00 - 18:00）
- 班次类型（必填）：现场值班 / 远程值班
- 值班地点（必填，下拉）
- 值班部门（必填，下拉，来源 `rev_department_config`）
- 值班人员（必填，下拉/多选）
- 按钮：取消、确认

#### 3.2.4 导入值班弹窗
- CSV 文件上传区域（拖拽/点击上传）
- 字段顺序说明：事项、日期、开始时间、结束时间、班次类型（site/remote）、值班地点、值班部门、值班人员（逗号分隔）
- 按钮：取消、确认导入（显示解析条数）

## 4. 数据库设计

### 4.0 公共字段规范（gauss `BaseEntity`）

所有新建表均继承 `gauss.boot.mybatis.entity.BaseEntity`，以下字段由框架统一维护，**不得遗漏**：

| 字段名 | 类型 | 必填 | 默认值 | 来源 | 说明 |
|--------|------|:----:|--------|------|------|
| id | bigint | 是 | - | `@TableId(type = IdType.ASSIGN_ID)` | 主键，雪花算法（与项目 `DepartmentConfig`/`AiRequestLog` 等实体一致） |
| version | int | 是 | 0 | gauss `BaseEntity`（`@Version` 乐观锁） | 版本号，由 `MetaObjectHandler` 自动填充 0 |
| create_by | varchar(50) | 否 | '' | gauss `BaseEntity` | 创建人域账号，自动填充 |
| create_name | varchar(50) | 否 | '' | 项目实体约定（如 `DepartmentConfig`、`AiRequestLog`） | 创建人姓名，自动填充 |
| create_time | timestamp | 否 | CURRENT_TIMESTAMP | gauss `BaseEntity` | 创建时间，自动填充 |
| update_by | varchar(50) | 否 | '' | gauss `BaseEntity` | 更新人域账号，自动填充 |
| update_name | varchar(50) | 否 | '' | 项目实体约定 | 更新人姓名，自动填充 |
| update_time | timestamp | 否 | CURRENT_TIMESTAMP | gauss `BaseEntity` | 更新时间，自动填充 |
| is_deleted | tinyint | 否 | 0 | gauss `BaseEntity`（`@TableLogic` 逻辑删除） | 是否删除 0-未删除 1-已删除 |

> 说明：上述字段与 `.docs/表结构设计.md` 中既有表的公共字段（version / create_by / create_time / update_by / update_time / is_deleted，较新的 `pm_*` 表另含 create_name / update_name）保持一致；逻辑删除、乐观锁、审计字段由 gauss 框架自动处理，业务代码无需手动赋值。

**同步规则**

| 场景 | 处理 |
|------|------|
| 新增/编辑值班 | 主表保存后先逻辑删除该值班旧明细，再按 `personList`（可选）或 `duty_persons` 拆分批量写入；随后将明细姓名拼接回写主表 `duty_person_names` |
| 删除值班 | 先逻辑删除主表记录，再逻辑删除其人员明细 |
| CSV 导入 | 批量保存主表后，逐条按 `duty_persons` 拆分写入明细并回写 `duty_person_names` |
| 值班详情 | 在 `DutyScheduleResponse.persons` 中返回人员明细（主表 `dutyPersons` 不变） |
| 日历/列表展示 | 直接使用主表 `duty_person_names`，无需 join 人员明细表 |

### 5.2 实体类示例

所有实体统一继承 gauss 框架 `BaseEntity`（已自带 `id / version / create_by / create_name / create_time / update_by / update_name / update_time / is_deleted` 等字段及自动填充逻辑），业务类只需声明业务字段：

```java
@Data
@Accessors(chain = true)
@EqualsAndHashCode(callSuper = true)
@JsonInclude(JsonInclude.Include.NON_NULL)
@TableName("duty_item")
public class DutyItem extends BaseEntity {
    @TableId(value = "id", type = IdType.ASSIGN_ID)
    private Long id;
    private String itemName;
    private LocalDate startDate;
    private LocalDate endDate;
}
```

```java
@Data
@Accessors(chain = true)
@EqualsAndHashCode(callSuper = true)
@JsonInclude(JsonInclude.Include.NON_NULL)
@TableName("duty_schedule")
public class DutySchedule extends BaseEntity {
    @TableId(value = "id", type = IdType.ASSIGN_ID)
    private Long id;
    private Long itemId;
    private LocalDate dutyDate;
    private String startTime;   // 原样保存，如 09:00
    private String endTime;     // 原样保存，如 18:00
    private String shiftType;
    private String locationCode;   // 字典编码
    private String locationName;   // 冗余
    private Long departmentId;
    private String departmentName;
    private String dutyPersons;
}
```

> 说明：
> - `BaseEntity` 来自 `gauss.boot.mybatis.entity.BaseEntity`，框架已处理 `version`（乐观锁）、`is_deleted`（逻辑删除）及审计字段的自动填充，业务代码无需手动赋值。
> - `id` 采用 `IdType.ASSIGN_ID`（雪花算法），实体字段类型用 `Long`，与 `DepartmentConfig`/`AiRequestLog` 等现有实体保持一致。
> - 仅在需要展示创建人姓名时补充 `createName`/`updateName` 字段（`@TableField(fill = FieldFill.INSERT / INSERT_UPDATE)`），其余审计字段由父类提供。

### 5.3 权限控制

#### 5.3.1 创建人判定
- 值班表 `duty_schedule.create_by` 记录当前登录人的域账号。
- 编辑/删除接口中校验：
  ```java
  GaussUser currentUser = UserUtils.getGaussUser();
  if (!Objects.equals(entity.getCreateBy(), currentUser.getUsername())) {
      throw new BusinessException("只有创建人可编辑/删除该值班记录");
  }
  ```

#### 5.3.2 管理员例外
- 如需管理员可编辑所有记录，可加入角色判断：
  ```java
  if (!isAdmin(currentUser) && !Objects.equals(entity.getCreateBy(), currentUser.getUsername())) {
      throw new BusinessException("只有创建人可编辑");
  }
  ```

### 5.4 核心业务逻辑

#### 5.4.1 日历查询
- 入参：`itemId`（可选）、`month`（格式 `yyyy-MM`，必填）。
- 计算月份起止日期，查询 `duty_schedule`。
- 返回按日期分组的数据结构，便于前端日历渲染。

#### 5.4.2 新增值班
- 校验时间：`start_time < end_time`。
- 校验班次类型在 `ShiftTypeEnum` 内、地点编码在 `DutyLocationEnum` 内、部门存在且未删除。
- 保存人员字符串（逗号分隔）到主表 `duty_persons`（原字段逻辑保持不变）。
- 同步写入 `duty_schedule_person` 明细：可选入参 `personList` 优先，否则按 `duty_persons` 逗号拆分。
- 明细写入后将姓名按排序拼接回写主表 `duty_person_names`，供列表/日历直接展示。

#### 5.4.3 编辑值班
- 仅允许创建人编辑。
- 更新时重新填充 `update_by/update_name/update_time`。
- 人员明细先逻辑删除后重建（主表 `duty_persons` 仍按原逻辑覆盖更新）。

#### 5.4.4 导入值班
- 解析 CSV，按模板字段顺序校验。
- 事项、地点（字典）、部门名称映射为数据库 ID/编码。
- 校验失败返回错误明细，成功返回导入数量。
- 主表批量保存后，逐条同步写入值班人员明细并回写 `duty_person_names`。

## 8. 导入导出设计

### 8.1 CSV 导入模板

字段顺序：

```
事项,日期,开始时间,结束时间,班次类型(site/remote),值班地点,值班部门,值班人员
```

示例：

```csv
全部事项值班安排,2026-08-01,09:00,18:00,site,四期,供应链智能部,陈晨,郑十,黄勇
```

> 注：截图说明中"值班人员（逗号分隔）"，即人员列内部用逗号分隔。

### 8.2 导入校验

- 必填字段缺失 → 返回行号及错误信息。
- 日期/时间格式错误 → 明确提示。
- 事项/部门名称不存在 → 返回未匹配明细。
- 地点只能使用 `DutyLocationEnum` 中的字典值（四期/六期/七期/老厂），非法值返回错误。
- 班次类型非法 → 仅允许 `site` / `remote`。

### 8.3 导出

- 导出字段与导入模板一致。
- 支持按当前筛选条件（事项、月份）导出。
- 使用 EasyExcel 实现，文件名如 `duty_schedule_202608.xlsx`。

## 11. 注意事项

1. **创建人唯一可编辑**：值班表必须记录 `create_by`，编辑/删除时严格校验，防止越权。
2. **事项时间范围约束**：建议校验值班日期是否在事项 `start_date` 与 `end_date` 范围内（可选，按业务确定）。
3. **部门、人员名称缓存**：日历查询中频繁需要名称展示，建议通过 join 查询或缓存避免 N+1（地点采用字典枚举，无需缓存）。
4. **不允许跨天**：值班时间段以 `varchar` 原样存储（前端传什么存什么，后端不格式化），新增/编辑与 CSV 导入均强制校验 `end_time > start_time`；跨天班次（如 `20:00-08:00`）需拆分为两条值班记录。
5. **导入幂等**：若同一事项、日期、时间、部门重复导入，可覆盖或提示重复，按业务确定。
6. **删除影响**：删除事项前应校验是否已被值班记录引用，避免数据悬空；地点为字典枚举，无需维护。
