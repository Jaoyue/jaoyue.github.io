# 值班日历接口文档（DutyController）

> 源码：`hinton-agent-mario-server-service/src/main/java/com/tineco/application/controller/duty/DutyController.java`  
> Swagger Tag：`值班日历`  
> 返回示例取自 2026-09 本地环境实测数据

## 1. 通用约定

| 项             | 说明                                                          |
| ------------- | ----------------------------------------------------------- |
| Context Path  | `/hinton-agent-mario-server`（`server.servlet.context-path`） |
| Controller 前缀 | `/api/duty`                                                 |
| 完整路径前缀        | `/hinton-agent-mario-server/api/duty`                       |
| 本地端口          | `8090`（local profile）；生产 `8080`                             |
| 请求编码          | `application/json;charset=UTF-8`（导入为 `multipart/form-data`） |
| 鉴权            | 沿用 gauss-boot-starter-security，请求需携带登录态                     |

### 1.1 统一响应结构

所有接口（导出、模板下载除外）返回 gauss 框架 `gauss.boot.common.dto.response.Result<T>`：

```json
{
  "code": 200,
  "message": "success",
  "data": { }
}
```

- `code = 200` 表示成功，其余为失败（`BusinessException` 由全局异常处理器捕获封装）。
- 导出 / 模板下载接口直接写 `HttpServletResponse` 二进制流，不走 `Result` 包装。

### 1.2 日期时间序列化（gauss 全局 Jackson 配置）

`SieJacksonConfiguration` 统一注册的序列化器：

| Java 类型       | 出参格式                  | 入参接受格式                |
| ------------- | --------------------- | --------------------- |
| LocalDate     | `yyyy-MM-dd`          | `yyyy-MM-dd`          |
| LocalDateTime | `yyyy-MM-dd HH:mm:ss` | `yyyy-MM-dd HH:mm:ss` |
| LocalTime     | `HH:mm:ss`            | `HH:mm:ss`            |

> **实测注意**：当前环境 `dutyDate`（`LocalDate` 类型）实际返回 `2026-09-07 00:00:00`（带时间后缀）。前端如需纯日期，建议统一 `substring(0, 10)` 截取前 10 位，不要写死格式判断。  
> `startTime` / `endTime` 在 `DutyScheduleResponse` 中已是 **String**（库中原始值），不受该配置影响，前端传什么返回什么。

### 1.3 数据字典

**班次类型 `shiftType`**（`ShiftTypeEnum`，编码为**大写**）

| code   | 名称   | 导入模板/Excel 填写     |
| ------ | ---- | ----------------- |
| SITE   | 现场值班 | `SITE` 或 `现场值班`   |
| REMOTE | 远程值班 | `REMOTE` 或 `远程值班` |

**值班地点 `locationCode`**（`DutyLocationEnum`，固定字典）

| code        | 名称 | 导入模板/Excel 填写 |
| ----------- | -- | ------------- |
| PHASE_4     | 四期 | 四期            |
| PHASE_6     | 六期 | 六期            |
| PHASE_7     | 七期 | 七期            |
| OLD_FACTORY | 老厂 | 老厂            |

> 新增/编辑接口传 **编码**（`PHASE_4`）；导入模板传 **中文名称**（`四期`）。  
> 班次类型在导入时**两种写法都兼容**（`ShiftTypeEnum.getCodeByCodeOrDesc`），地点**只认中文名称**（`DutyLocationEnum.ofDesc`）。

## 3. 事项管理

### 3.1 新增事项

- **POST** `/hinton-agent-mario-server/api/duty/item/addOrUpdate`
- 入参：`DutyItemVO`（`@Valid`）

| 字段        | 类型        |  必填 | 校验          | 说明                  |
| --------- | --------- | :-: | ----------- | ------------------- |
| id        | Long      |  否  | -           | 主键ID；**不传=新增，传=编辑** |
| itemName  | String    |  是  | `@NotBlank` | 事项名称                |
| startDate | LocalDate |  是  | `@NotNull`  | 开始日期 `yyyy-MM-dd`   |
| endDate   | LocalDate |  是  | `@NotNull`  | 结束日期 `yyyy-MM-dd`   |

**请求示例（新增）**

```json
{
  "itemName": "大促值班安排",
  "startDate": "2026-09-01",
  "endDate": "2026-09-30"
}
```

**请求示例（编辑）**

```json
{
  "id": 2094975399103713281,
  "itemName": "大促值班安排",
  "startDate": "2026-09-01",
  "endDate": "2026-10-31"
}
```

**返回字段说明** `Result<Long>`

| 字段      | 类型      | 说明                                            |
| ------- | ------- | --------------------------------------------- |
| code    | Integer | `200` 成功                                      |
| message | String  | `success`                                     |
| data    | Long    | 事项主键ID（雪花 ID，序列化为字符串，如 `2094975399103713281`） |

```json
{ "code": 200, "message": "success", "data": "2094975399103713281" }
```

**业务异常**

| 场景         | 消息             |
| ---------- | -------------- |
| 结束日期早于开始日期 | `结束日期不能早于开始日期` |
| 编辑时 ID 不存在 | `事项不存在或已删除`    |

**请求示例**

| data[].createBy   | String | 创建人域账号                  |

## 4. 值班安排

### 4.1 按月查询值班日历

- **POST** `/hinton-agent-mario-server/api/duty/schedule/calendar`
- 入参：`DutyScheduleQueryVO`（**`required = false`，body 可不传**）

| 字段     | 类型     |  必填 | 说明                         |
| ------ | ------ | :-: | -------------------------- |
| itemId | Long   |  否  | 事项ID；不传/传 null 查全部事项       |
| month  | String |  否  | 月份 `yyyy-MM`；**不传或空串默认当月** |

**请求示例**

```json
{ "itemId": null, "month": "2026-09" }
```

也允许直接 `POST` 空 body：`{}`（默认当月 + 全部事项）。

**返回字段说明** `Result<DutyCalendarResponse>`

| 字段                    | 类型      | 说明                                                                 |
| --------------------- | ------- | ------------------------------------------------------------------ |
| data.month            | String  | **实际查询的月份** `yyyy-MM`，未传月份时回填为当月；前端可用它做月份回显                        |
| data.total            | Integer | 该月**值班记录总条数**（不是天数，也不是有值班的天数）                                      |
| data.items            | Map     | **按日期分组的值班列表**，key = `yyyy-MM-dd`，value = 当天值班数组                   |
| data.items            | —       | **补齐当月每一天**（1 号到月末），当天无值班返回**空数组 `[]`**，不会出现缺 key 的情况              |
| data.items\[date\]\[] | Array   | 当天的值班条目，按 `duty_date ASC, start_time ASC, id ASC` 排序（同一天多条按开始时间先后） |

`data.items[date][]` 元素（`DutyScheduleResponse`）

| 字段              | 类型     | 说明                                                          |
| --------------- | ------ | ----------------------------------------------------------- |
| id              | String | 值班主键ID                                                      |
| itemId          | String | 事项ID                                                        |
| itemName        | String | 事项名称（关联 `duty_item` 冗余展示）                                   |
| dutyDate        | String | 值班日期，实测格式 `yyyy-MM-dd`                                      |
| startTime       | String | 开始时间，**库中原始值原样返回**，如 `09:00` / `18:00`                      |
| endTime         | String | 结束时间，**库中原始值原样返回**，如 `18:00` / `20:00`                      |
| shiftType       | String | 班次类型编码，**大写**：`SITE` / `REMOTE`                             |
| shiftTypeName   | String | 班次类型中文名：`现场值班` / `远程值班`                                     |
| locationCode    | String | 值班地点编码：`PHASE_4` / `PHASE_6` / `PHASE_7` / `OLD_FACTORY`    |
| locationName    | String | 值班地点名称（冗余字段，为空时按编码反查枚举补全）                                   |
| departmentId    | String | 值班部门ID（`rev_department_config.id`）                          |
| departmentName  | String | 值班部门名称（冗余）                                                  |
| dutyPersons     | String | **值班人员域账号**，逗号分隔，如 `zhangsan,wangwu`                        |
| dutyPersonNames | String | **值班人员姓名**，逗号分隔，如 `张三,王五` —— 日历/列表展示用这个                     |
| persons         | Array  | 人员明细；**日历接口不返回**（为 `null`，部分环境序列化时被忽略、字段不出现），需要明细调 4.3 值班详情 |
| createBy        | String | 创建人域账号 —— **前端用它判断当前登录人能否编辑/删除**                            |
| createName      | String | 创建人姓名                                                       |

### 4.2 新增/编辑值班

- **POST** `/hinton-agent-mario-server/api/duty/schedule/addOrUpdate`
- 入参：`DutyScheduleVO`（`@Valid`）

| 字段           | 类型        |   必填  | 校验          | 说明                                                     |
| ------------ | --------- | :---: | ----------- | ------------------------------------------------------ |
| id           | Long      |   否   | -           | 主键ID；**不传=新增，传=编辑**（编辑需为创建人）                           |
| itemId       | Long      |   是   | `@NotNull`  | 事项ID                                                   |
| dutyDate     | LocalDate |   是   | `@NotNull`  | 值班日期 `yyyy-MM-dd`                                      |
| startTime    | String    |   是   | `@NotBlank` | 开始时间，**原样保存**，如 `09:00`                                |
| endTime      | String    |   是   | `@NotBlank` | 结束时间，**原样保存**，如 `18:00`；**必须晚于开始时间，不允许跨天**             |
| shiftType    | String    |   是   | `@NotBlank` | 班次类型编码，**大写**：`SITE` / `REMOTE`                        |
| locationCode | String    |   是   | `@NotBlank` | 地点编码：`PHASE_4` / `PHASE_6` / `PHASE_7` / `OLD_FACTORY` |
| departmentId | Long      |   是   | `@NotNull`  | 值班部门ID（`rev_department_config.id`）                     |
| personList   | Array     | **是** | `@NotEmpty` | 值班人员列表，见下                                              |

`personList[]` 元素（`DutySchedulePersonVO`）— **姓名与域账号均为必填**

| 字段             | 类型      |  必填 | 校验          | 说明                     |
| -------------- | ------- | :-: | ----------- | ---------------------- |
| personAccount  | String  |  是  | `@NotBlank` | 值班人员域账号；**同一值班内不允许重复** |
| personName     | String  |  是  | `@NotBlank` | 值班人员姓名                 |
| personDeptName | String  |  否  | -           | 值班人员所属部门（冗余，可不传）       |
| sortOrder      | Integer |  否  | -           | 排序；不传按传入顺序             |

**请求示例（新增）**

```json
{
  "itemId": 2094975399103713281,
  "dutyDate": "2026-09-07",
  "startTime": "18:00",
  "endTime": "20:00",
  "shiftType": "SITE",
  "locationCode": "PHASE_6",
  "departmentId": 2,
  "personList": [
    { "personAccount": "zhangsan", "personName": "张三", "personDeptName": "国际营销智能部" },
    { "personAccount": "wangwu", "personName": "王五", "personDeptName": "国际营销智能部" }
  ]
}
```

**请求示例（编辑）**

```json
{
  "id": 2094990093575254018,
  "itemId": 2094975399103713281,
  "dutyDate": "2026-09-07",
  "startTime": "18:00",
  "endTime": "22:00",
  "shiftType": "REMOTE",
  "locationCode": "PHASE_6",
  "departmentId": 2,
  "personList": [
    { "personAccount": "zhangsan", "personName": "张三", "sortOrder": 0 },
    { "personAccount": "wangwu", "personName": "王五", "sortOrder": 1 }
  ]
}
```

**返回字段说明** `Result<Long>`

| 字段   | 类型   | 说明                                     |
| ---- | ---- | -------------------------------------- |
| data | Long | 值班主键ID（字符串序列化），如 `2094990093575254018` |

```json
{ "code": 200, "message": "success", "data": "2094990093575254018" }
```

**落库行为**（前端需知晓的副作用）

- `duty_schedule.duty_persons` ← `personList` 的 **域账号** 逗号拼接
- `duty_schedule.duty_person_names` ← `personList` 的 **姓名** 逗号拼接
- `duty_schedule_person` 明细表：先逻辑删除旧明细，再按 `personList` 重建

**业务异常**

| 场景        | 消息                                                         |
| --------- | ---------------------------------------------------------- |
| 班次类型非法    | `班次类型非法，仅允许 SITE/REMOTE`                                   |
| 地点编码非法    | `值班地点非法，请使用字典编码：PHASE_4 / PHASE_6 / PHASE_7 / OLD_FACTORY` |
| 事项不存在     | `事项不存在或已删除`                                                |
| 部门不存在     | `值班部门不存在`                                                  |
| 时间为空 / 跨天 | `开始时间和结束时间不能为空` / `值班不允许跨天，结束时间必须晚于开始时间`                   |
| 人员为空      | `值班人员不能为空`                                                 |
| 人员缺字段     | `值班人员姓名与域账号不能为空`                                           |
| 人员域账号重复   | `值班人员不允许重复：{account}`                                      |
| 编辑时记录不存在  | `值班记录不存在或已删除`                                              |
| 非创建人      | `只有创建人可编辑/删除该值班记录`                                         |

### 4.3 值班详情

- **GET** `/hinton-agent-mario-server/api/duty/schedule/getDetail`
- 入参：QueryString

| 字段 | 类型   |  必填 | 说明     |
| -- | ---- | :-: | ------ |
| id | Long |  是  | 值班主键ID |

**请求示例**

### 4.6 导入值班日历

- **POST** `/hinton-agent-mario-server/api/duty/schedule/import`
- Content-Type：**`multipart/form-data`**
- 入参：

| 字段   | 类型            |  必填 | 说明                                               |
| ---- | ------------- | :-: | ------------------------------------------------ |
| file | MultipartFile |  是  | **Excel 文件**（`.xlsx`），列定义见 4.5，建议直接用 4.5 下载的模板填写 |

> 与历史版本区别：**已由 CSV 改为 Excel（EasyExcel）解析**，旧 CSV 文件不再支持。

**返回字段说明** `Result<Integer>`

| 字段   | 类型      | 说明            |
| ---- | ------- | ------------- |
| data | Integer | 成功导入的**记录条数** |

```json
{ "code": 200, "message": "success", "data": 6 }
```

**落库行为**

- `dutyPersons`（域账号列）→ `duty_schedule.duty_persons`
- `dutyPersons`（姓名列）→ `duty_schedule.duty_person_names`
- 批量保存主表后，逐条同步写入 `duty_schedule_person` 明细并回写主表冗余字段

**校验规则（全量校验，任一行出错整批不落库）**

| 场景                 | 错误消息                                             |
| ------------------ | ------------------------------------------------ |
| 文件为空 / 无数据         | `导入文件为空` / `导入文件无有效数据`                           |
| 读取失败               | `读取导入文件失败：{msg}`                                 |
| 必填字段为空（含人员与域账号都为空） | `第N行：存在必填字段为空`                                   |
| 人员数与域账号数不一致        | `第N行：值班人员（X 人）与域账号（Y 个）数量不一致`                    |
| 班次类型非法             | `第N行：班次类型[xxx]非法，仅允许：现场值班/远程值班`                  |
| 地点非法               | `第N行：值班地点[xxx]非法，仅允许：四期/六期/七期/老厂`                |
| 日期格式错误             | `第N行：日期格式错误[xxx]，应为 yyyy-MM-dd`                  |
| 时间被 Excel 转成数字     | `第N行：开始时间[0.375]格式错误，请按文本填写（如 09:00）`            |
| 时间为空 / 跨天          | `第N行：开始时间和结束时间不能为空` / `第N行：值班不允许跨天，结束时间必须晚于开始时间` |
| 事项不存在              | `第N行：事项[xxx]不存在`                                 |
| 部门不存在              | `第N行：值班部门[xxx]不存在`                               |

> 行号 `N` 从 **2** 开始（第 1 行为表头），与 Excel 行号一致，方便用户定位。  
> 错误会全部收集后一次性抛出，message 形如 `导入数据校验失败：\n第3行：...\n第5行：...`。  
> **容错点**：日期列若被 Excel 自动转成日期类型，读到的是 1900 起的序列值（如 `2026-08-01` → `46235`），会自动换算回正确日期；但时间列被转成小数（`09:00` → `0.375`）无意义，会明确报错。

## 6. 备注 / 易踩坑

1. **ID 全部是字符串**：所有响应中的 `id` / `itemId` / `departmentId` / `scheduleId` 都用 `ToStringSerializer` 输出为字符串，避免 JS 精度丢失；请求入参传数字或字符串都能反序列化成 Long。
2. **`dutyPersons` 与 `dutyPersonNames` 别搞混**：前者是**域账号**，后者是**姓名**。日历展示用 `dutyPersonNames`。
3. **`personList` 现在是必填**，且每项必须同时有 `personAccount` 和 `personName`，域账号不可重复 —— 之前按 `dutyPersons` 逗号字符串拆分的写法已废弃。
4. **不允许跨天**：新增/编辑与导入都会校验结束时间必须晚于开始时间（`20:00 → 08:00` 会被拒绝）。
5. **班次类型编码已改大写**：`SITE` / `REMOTE`（之前设计文档写的是 `site` / `remote`）。
6. **日历接口补齐整月**：无值班的日期返回空数组，前端不需要自己补 key，可直接 `Object.entries(items)` 渲染。
7. **权限**：编辑/删除值班后端按 `create_by` 与当前登录人域账号比对，前端可用 `createBy` 控制按钮显隐，但最终校验在后端（异常：`只有创建人可编辑/删除该值班记录`）。
8. **`month` 可不传**：日历查询与导出都不传月份时默认当月，响应/文件名中会回填实际月份。
