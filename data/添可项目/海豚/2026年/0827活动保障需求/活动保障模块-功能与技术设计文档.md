# 活动保障功能设计文档  
  
> **版本**: 1.0    
> **模块**: ops（运营运维域）  > **分支**: dev_活动保障  > **最后更新**: 2026-08-28  
  
---  
  
## 一、模块概述  
  
"活动保障"是 ops 运营运维域下的新功能模块，参照"系统问题与故障"模块的架构模式设计，负责活动保障的全生命周期管理。该模块实现从活动提报、AI 活动方案生成与守门、AI 行动计划生成与闭环、到活动复盘的完整流程。  
  
### 核心能力  
  
| 能力 | 说明 |  
|------|------|  
| 活动提报 | 人工填报活动信息，支持多时间轴，自动生成活动编号（ATHB） |  
| AI 活动方案 | 调用珊瑚 AI 工作流自动生成活动等级、保障部门、保障负责人、方案文本 |  
| 方案纠偏与守门 | AI 活动方案支持人工纠偏，硅基/碳基两级守门 |  
| AI 行动计划 | AI 活动方案触发珊瑚 AI 行动计划流程，生成行动计划 |  
| 行动计划闭环 | 行动计划支持编辑、守门、推送任务中心、新增计划、重新生成 |  
| 活动复盘 | 关联活动时间内故障/问题，调用珊瑚复盘工作流，支持版本切换、守门、提交 |

## 三、状态流转设计  
  
### 3.1 活动状态 `activity_status`  
  
```  
PENDING（待保障）  
  │  ├── 触发 AI 行动计划生成（方案守门后）  
  │  ▼PROCESSING（保障中）  
  │  ├── 全部行动计划守门完成  
  │  ▼COMPLETED（已完成）  
  │  ├── 提交复盘  
  │  ▼REVIEWED（已复盘）  
```  
  
| 状态值 | 描述 | 触发条件 |  
|--------|------|----------|  
| `PENDING` | 待保障 | 新增活动时初始状态 |  
| `PROCESSING` | 保障中 | AI 行动计划生成后 |  
| `COMPLETED` | 已完成 | 所有行动计划均已守门 |  
| `REVIEWED` | 已复盘 | 复盘提交后 |  
  
### 3.2 AI 活动方案状态 `ai_plan_status`  
  
```  
NOT_GENERATED（未生成）──新增触发──> GENERATED（已生成）──重新生成──> REGENERATED（已重新生成）  
```  
  
### 3.3 AI 分析状态 `ai_analysis_status`  
  
```  
PENDING（分析中）──> SUCCESS（分析成功）/ FAILED（分析失败）  
```  
  
### 3.4 方案守门状态 `plan_guard_flag`  
  
```  
NOT_GUARDED（未守门）──纠偏或守门──> SILICON_GUARDED（硅基守门）/ CARBON_GUARDED（碳基守门）  
```  
  
**守门判定规则**（参照故障模块 `recomputeGuardStatus`）：  
- 方案生成后未经人工编辑 → `SILICON_GUARDED`（硅基守门）  
- 方案经过人工纠偏后 → `CARBON_GUARDED`（碳基守门）  
- 守门通过后方可触发 AI 行动计划生成  
  
### 3.5 AI 行动计划状态 `ai_action_status`  
  
```  
NOT_GENERATED（未生成）──触发──> GENERATED（已生成）──重新生成──> REGENERATED（已重新生成）  
```  
  
### 3.6 行动计划守门状态（同故障模块）  
  
```  
NOT_GUARDED ──批注或推送任务──> GUARDED（SILICON_GUARDED / CARBON_GUARDED）  
```  
  
### 3.7 复盘状态 `review_status`  
  
```  
DRAFT（草稿）──触发复盘──> REVIEWING（复盘中）──提交──> SUBMITTED（已提交）  
```

## 五、核心业务流程  
  
### 5.1 活动提报 + AI 活动方案生成流程  
  
```  
用户填报活动信息  
    │  字段：活动名称、提报人、保障负责人（只读，AI 填充后回显）、  
    │       活动描述、活动起止时间、活动附件、活动时间轴（多个）  
    │    ▼addOrUpdate (新增)  
    │  1. 生成活动编号：InitializeCodeUtil.generateOrderNo("ATHB")  
    │     格式：ATHB + yyyyMMdd + 5位序号，如 ATHB2026082800001    │  2. 设置提报人信息（从登录用户获取）  
    │  3. 活动状态 → PENDING    │  4. AI 方案状态 → NOT_GENERATED    │  5. AI 分析状态 → PENDING    │  6. 保存活动时间轴（批量插入）  
    │  7. 保存活动附件（RevAttachmentService，businessType=401）  
    │    ▼doActivityPlan (调用珊瑚 AI 活动方案工作流)  
    │  构建表单：活动名称、活动描述、活动起止时间、时间轴列表、提报人、保障部门  
    │  调用珊瑚流程：APP_NAME_ACTIVITY_PLAN  
    │  解析 AI 返回 JSON    │    ├── 成功 → 填充 AI 字段：  
    │     │     ai_activity_level（重大保障/常规保障）  
    │     │     assurance_dept_ai（保障部门）  
    │     │     assurance_leader_ai + assurance_leader_id_ai（保障负责人）  
    │     │     ai_plan_text（方案文本）  
    │     │     回填主表 assurance_dept / assurance_leader / assurance_leader_id    │     │     AI 分析状态 → SUCCESS    │     │     AI 方案状态 → GENERATED    │    └── 失败 → AI 分析状态 → FAILED    │    ▼落库（updateById）  
    │    ▼返回活动详情（含 AI 方案）  
```  
  
### 5.2 AI 活动方案纠偏与守门流程  
  
```  
AI 方案生成完成  
    │    ├── 方案守门（plan/guard）  
    │     │  未经人工编辑 → SILICON_GUARDED（硅基守门）  
    │     │  方案守门状态 → GUARDED    │     │  允许触发 AI 行动计划  
    │     ▼    │    └── 方案纠偏（plan/correct）  
          │  校验：仅提报人直属上级可纠偏  
          │  更新人工方案字段：  
          │     activity_level（人工活动等级）  
          │     assurance_dept（人工保障部门）  
          │     assurance_leader / assurance_leader_id（人工保障负责人）  
          │     manual_plan_text（人工方案文本）  
          │  标记 is_edited=1          │  守门类型 → CARBON_GUARDED（碳基守门）  
          │  方案守门状态 → GUARDED          │  允许触发 AI 行动计划  
          ▼```  
  
### 5.3 AI 行动计划生成流程  
  
```  
方案守门通过后，用户触发 generateActionPlan(id)    │    ▼校验：方案守门状态为 GUARDED    │    ▼callCoralForActionPlans (调用珊瑚 AI 行动计划流程)  
    │  构建表单：  
    │     活动名称、活动描述  
    │     AI 方案文本（或人工纠偏后的方案文本）  
    │     活动等级、保障部门、保障负责人  
    │     时间轴信息  
    │  调用珊瑚流程：APP_NAME_ACTIVITY_ACTION_PLAN  
    │  解析返回 JSON（兼容数组/对象包裹数组/单对象格式）  
    │  根据域账号查询责任人姓名  
    │    ▼initActionPlans (初始化行动计划：守门状态置 NOT_GUARDED)    │    ▼persistActionPlans (覆盖式持久化：先删后插)  
    │    ▼更新活动：活动状态 → PROCESSING，AI行动计划状态 → GENERATED    │    ▼submitGateTask (向提报人直属上级推送守门任务)  
    │  1. 通过域账号查询提报人 → 获取工号  
    │  2. 查询提报人直属上级（OrganizationService.getDirectSupervisor）  
    │  3. 构建守门任务（名称、描述、目标、计划完成时间 +24h）  
    │  4. 推送至任务中心（submitFaultTask）  
    │  5. 回写 task_platform_task_id```  
  
### 5.4 行动计划守门闭环流程  
  
> 完全复用系统问题与故障模块的守门闭环逻辑。  
  
```  
提报人直属上级收到守门任务  
    │    ├── 编辑行动计划 (action/edit)    │     │  校验当前用户是提报人直属上级  
    │     │  更新计划内容 → 标记 is_edited=1    │     │  重算守门状态 → CARBON_GUARDED    │     │  记录编辑操作日志  
    │     │  责任人变更 → 额外记录变更日志  
    │     ▼    │    ├── 添加批注 (action/annotate)    │     │  校验当前用户是提报人直属上级  
    │     │  更新批注 → 标记 is_annotated=1    │     │  重算守门状态  
    │     │  检查全部守门 → 若是，活动置 COMPLETED + 关闭守门任务  
    │     │  记录批注操作日志  
    │     ▼    │    └── 推送执行任务 (action/pushTask)          │  校验当前用户是提报人直属上级  
          │  校验责任人域账号存在  
          │  构建执行任务 → 推送至任务中心  
          │  标记 is_pushed=1，task_status → IN_PROGRESS  
          │  重算守门状态  
          │  检查全部守门 → 若是，活动置 COMPLETED + 关闭守门任务  
          │  记录推送任务操作日志  
          ▼  
全部行动计划守门完成  
    │    ▼resolveActivityIfAllGuarded  
    │  统计：total = 行动计划总数，guarded = 已守门数  
    │  若 total > 0 且 guarded == total    │  → 活动状态置 COMPLETED    │  → completeOrderTask (关闭任务中心守门任务)  
```  
  
### 5.5 重新生成 AI 行动计划流程  
  
```  
用户触发 regenerateActionPlan(id)    │    ▼校验：已复盘状态不可重新生成  
    │    ▼callCoralForActionPlans → initActionPlans → persistActionPlans (覆盖)  
    │    ▼更新活动：AI行动计划状态 → REGENERATED    │    ▼返回最新详情（守门状态已重置）  
```  
  
### 5.6 活动复盘流程  
  
```  
活动状态为 COMPLETED，用户点击"复盘"按钮  
    │    ▼进入复盘页面（字段带出）：  
    │  活动名称（只读）、活动开始时间（只读）、活动结束时间（只读）  
    │  AI 活动等级（只读）、活动描述（只读）  
    │    ▼查询关联故障/问题 (relatedFaults)    │  根据活动起止时间查询 ops_system_fault_submission 表  
    │  条件：occurrenc_time BETWEEN activity.start_time AND activity.end_time  
    │  返回故障列表供用户多选  
    │    ▼用户选择关联故障，点击"发起复盘" (review/start)  
    │  1. 保存关联故障 ID 列表到 review.related_fault_ids    │  2. 根据故障 ID 列表查询 ops_system_fault_submission 表，获取故障详情  
    │  3. 将每个故障的以下字段拼接成一个字符串，保存到 review.fault_detail_text：  
    │     产品模块(product_module)、产品名称(product_name)、提报人(submitter_name)、  
    │     所属部门(department)、故障描述(problem_description)、等级(fault_level)、  
    │     状态(handling_status)、AI故障恢复方案(recovery_plan_ai)、  
    │     AI根本解决方案(fundamental_solution_ai)、故障时长(fault_duration)、  
    │     影响范围(impact_scope)、发生时间(occurrenc_time)、  
    │     实际故障恢复时间(actual_recovery_time)  
    │     多个故障以分隔符拼接  
    │  4. 复盘状态 → REVIEWING    │  5. 生成 requestId（UUID）  
    │  6. 构建珊瑚复盘表单：  
    │     活动名称、活动描述、活动等级、活动起止时间  
    │     fault_detail_text（拼接后的故障详情文本）  
    │     行动计划执行情况  
    │  7. 调用珊瑚复盘工作流（APP_NAME_ACTIVITY_REVIEW）  
    │  8. AI 返回复盘报告  
    │  9. 保存为 V1 版本（ops_activity_review_version）  
    │  10. 回填 ai_review_report    │    ▼复盘报告可操作：  
    │    ├── 编辑复盘报告 (review/edit)    │     │  保存为新版本（V2, V3, ...）  
    │     │  标记 is_edited=1    │     │  守门类型 → CARBON_GUARDED    │     │  当前版本标记 is_current=1，其他版本置 0    │     ▼    │    ├── 切换版本 (review/switchVersion)    │     │  指定版本号，将该版本标记 is_current=1    │     │  回填当前复盘报告内容  
    │     ▼    │    ├── 守门 (review/guard)    │     │  未经编辑 → SILICON_GUARDED    │     │  经过编辑 → CARBON_GUARDED    │     │  guard_flag → GUARDED    │     ▼    │    └── 提交复盘 (review/submit)          │  校验：守门状态为 GUARDED          │  复盘状态 → SUBMITTED          │  活动状态 → REVIEWED          │  记录复盘提交时间  
          │  关闭任务中心任务（如有）  
          ▼```

## 七、任务中心集成  
  
> 完全复用系统问题与故障模块的任务中心集成模式。  
  
### 7.1 守门任务（GATE 任务）  
  
- **触发时机**: AI 行动计划生成后  
- **推送对象**: 提报人直属上级  
- **任务名称**: `请关注活动保障 {活动编号}，由 {提报人} 创建，AI行动计划已生成，需进行守门`  
- **任务目标**: `完成活动保障，AI行动计划守门，并推送任务给责任人`  
- **计划完成时间**: 当前时间 + 24 小时  
- **任务前缀**: `GATE_`  
- **关闭条件**: 活动下所有行动计划均已守门  
  
### 7.2 执行任务（EXEC 任务）  
  
- **触发时机**: 提报人直属上级推送执行任务  
- **推送对象**: 行动计划责任人  
- **任务名称**: 行动计划标题  
- **任务目标**: `{活动编号}行动计划执行落地完成 {目标}`  
- **计划完成时间**: 行动计划的预计完成时间  
- **任务前缀**: `EXEC_`  
- **调用方法**: `submitFaultTask007`（使用 `accessKey_007`）

## 十四、权限控制  
  
### 14.1 行动计划操作权限  
  
与系统问题与故障模块一致，行动计划编辑、批注、推送执行任务均需校验当前操作人是否为活动提报人的直属上级。  
  
**校验方法**: `assertCurrentUserIsSubmitterSupervisor`（复用故障模块逻辑）  
  
### 14.2 方案纠偏权限  
  
AI 活动方案纠偏操作同样需校验提报人直属上级权限。  
  
### 14.3 复盘权限  
  
- 发起复盘：活动状态为 COMPLETED 时可操作  
- 提交复盘：复盘守门状态为 GUARDED 时可操作

## 十六、关键业务规则总结  
  
1. **AI 自动触发**: 新增活动后自动调用珊瑚 AI 活动方案工作流  
2. **三级 AI 流程**: 活动方案 → 行动计划 → 活动复盘  
3. **方案守门前置**: 方案守门通过后方可触发 AI 行动计划生成  
4. **方案纠偏影响守门**: 纠偏后守门类型从硅基变为碳基  
5. **行动计划完全复用**: 守门、编辑、批注、推送、重新生成逻辑与故障模块一致  
6. **自动闭环**: 所有行动计划守门完成后，活动状态自动置为已完成  
7. **关联故障查询与拼接**: 复盘时根据活动时间范围查询 `ops_system_fault_submission` 表，选择后将故障 ID 保存，并将每个故障的产品模块、产品名称、提报人、所属部门、故障描述、等级、状态、两个 AI 方案、故障时长、影响范围、发生时间、实际故障恢复时间拼接成字符串传给复盘工作流  
8. **复盘无附件**: 活动复盘不涉及附件上传，仅通过工作流生成报告  
9. **复盘版本管理**: 每次 AI 生成或人工编辑均保存版本，支持切换  
10. **复盘守门提交**: 复盘报告守门通过后方可提交，提交后活动状态置为已复盘  
11. **保障负责人只读**: 提报时保障负责人只读，由 AI 方案自动填充
