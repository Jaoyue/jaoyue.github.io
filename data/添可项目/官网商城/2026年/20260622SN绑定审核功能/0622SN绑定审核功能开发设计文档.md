## 1. 项目架构概览

### 1.1 技术栈

| 技术 | 版本/说明 |
|------|-----------|
| 框架 | Spring Boot + MyBatis |
| ORM | MyBatis（无 MyBatis-Plus） |
| 事务 | `DataSourceTransactionManager`（多数据源） |
| 分布式锁 | Redisson |
| 分页 | PageHelper |

| API 文档 | Swagger（`@Api` / `@ApiOperation`） |

### 1.2 多数据源架构

```
java_goods (主库，merchant 业务表)
├── gdb_merchant_user_bind          ← 用户绑定表（现有）
├── gdb_merchant_code_management    ← 商品编码表（现有）
├── gdb_merchant_sn_binding_audit   ← SN审核表（新增）
└── ...

├── udb_ucenter_user_info
└── ...
```

> **关键约定：** 审核表使用 `ucenterTransactionManager` 事务管理器，通过 SQL 显式指定 schema（`java_goods.gdb_merchant_sn_binding_audit`）进行跨库操作。

## 2. 数据库设计

### 2.1 命名规则说明

项目现有表遵循统一前缀规则：

```
java_goods.gdb_merchant_{snake_case_entity_name}
```

| 现有表 | 含义 |
|--------|------|
| `gdb_merchant_user_bind` | 用户产品绑定 |
| `gdb_merchant_code_management` | 商品编码管理 |
| `gdb_merchant_shop_bankcard_audit` | 店铺银行卡审核（已有审核表范例） |

**新增审核表命名：** `gdb_merchant_sn_binding_audit`

### 2.2 新增审核表 DDL

```sql
-- 归属数据库: java_goods
-- 与 gdb_merchant_user_bind 同源
CREATE TABLE `gdb_merchant_sn_binding_audit` (
  `id`                  BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id`             INT          NOT NULL COMMENT '申请人用户ID',
  `user_mobile`         VARCHAR(20)  NOT NULL COMMENT '申请人手机号',
  `sn_code`             VARCHAR(100) NOT NULL COMMENT 'SN码（大写）',
  `product_name`        VARCHAR(200)          COMMENT '产品名称（申请时记录，来自GOMS）',
  `sn_photo_urls`       TEXT                  COMMENT 'SN实物图URL列表，逗号分隔',
  `receipt_photo_urls`  TEXT                  COMMENT '购买凭证图URL列表，逗号分隔',
  `status`              TINYINT      NOT NULL DEFAULT 0 COMMENT '审核状态：0-待审核，1-审核通过，2-审核不通过',
  `reject_reason`       VARCHAR(500)          COMMENT '审核不通过原因',
  `apply_time`          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '申诉申请时间',
  `audit_time`          DATETIME              COMMENT '审核操作时间',
  `auditor_id`          INT                   COMMENT '审核人用户ID',
  `create_time`         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
  `update_time`         DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '记录更新时间',
  PRIMARY KEY (`id`),
  INDEX `idx_sn_code`    (`sn_code`),
  INDEX `idx_user_mobile`(`user_mobile`),
  INDEX `idx_user_id`    (`user_id`),
  INDEX `idx_status`     (`status`),
  INDEX `idx_apply_time` (`apply_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='SN绑定申诉审核表';
```

### 2.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT AUTO_INCREMENT | 自增主键 |
| `user_id` | INT | 申请人用户ID |
| `user_mobile` | VARCHAR(20) | 申请人手机号 |
| `sn_code` | VARCHAR(100) | SN码，存储时转大写 |
| `product_name` | VARCHAR(200) | 产品名称（申请时从 GOMS 获取） |
| `sn_photo_urls` | TEXT | SN实物图URL，逗号分隔 `url1,url2` |
| `receipt_photo_urls` | TEXT | 购买凭证图URL，逗号分隔 |
| `status` | TINYINT DEFAULT 0 | 0=待审核/1=通过/2=不通过 |
| `reject_reason` | VARCHAR(500) | 审核不通过时必填 |
| `apply_time` | DATETIME | 申诉提交时的服务器时间 |
| `audit_time` | DATETIME | 审核操作时的服务器时间 |
| `auditor_id` | INT | 审核管理员用户 ID |
| `create_time` | DATETIME | 记录创建时间 |
| `update_time` | DATETIME | 记录更新时间 |

> **图片存储格式：** 前端传逗号分隔字符串 `url1,url2`，后端直接存字符串，查询返回字符串，前端自行 split。

### 2.4 索引设计理由

| 索引 | 用途 |
|------|------|
| `PRIMARY KEY (id)` | 主键索引 |
| `idx_sn_code` | 用户按 SN 码查询申诉状态（高频） |
| `idx_user_mobile` | 后台按手机号模糊搜索（高频） |
| `idx_user_id` | 按用户 ID 查询历史申诉记录 |
| `idx_status` | 按审核状态筛选（高频） |
| `idx_apply_time` | 按申请时间排序 |

```java
@ApiOperation(value = "提交SN绑定申诉")
@PostMapping("/apply")
public ResultResp apply(@Valid @RequestBody SnBindingAuditApplyReq req) {
    // 1. 登录态校验
    UserInfo currentUser = AuthUserContext.get();
    AssertUtil.state(ObjectUtil.isNotNull(currentUser),
            new BizException("登录信息已失效，请重新登录"));

    // 2. SN 码转大写
    String snCode = req.getSnCode().toUpperCase();

    // 3. 构建 DO
    SnBindingAuditDo auditDo = new SnBindingAuditDo();
    auditDo.setUserId(currentUser.getUserId());
    auditDo.setUserMobile(currentUser.getUserMobile());
    auditDo.setSnCode(snCode);
    auditDo.setSnPhotoUrls(req.getSnPhotoUrls());        // 逗号分隔字符串
    auditDo.setReceiptPhotoUrls(req.getReceiptPhotoUrls());
    auditDo.setStatus(0);
    auditDo.setApplyTime(new Date());

    snBindingAuditService.apply(auditDo);

    // 4. 构建响应
    SnBindingAuditStatusResp resp = new SnBindingAuditStatusResp();
    resp.setId(auditDo.getId());
    resp.setSnCode(snCode);
    resp.setStatus(0);
    resp.setApplyTime(auditDo.getApplyTime());

    return new ResultResp(1, resp, null);
}
```

**图片存储格式：** 前端传逗号分隔字符串，后端直接存字符串，不做 JSON 转换。

```java
// com.yf.platform.ucenter.domain.req.SnBindingAuditActionReq
@ApiModel(value = "SN绑定审核操作请求")
@Getter @Setter
public class SnBindingAuditActionReq {
    @ApiModelProperty(value = "审核记录ID", required = true)
    @NotNull(message = "审核记录ID不能为空")
    private Long id;

    @ApiModelProperty(value = "审核动作: pass-通过, reject-不通过", required = true)
    @NotBlank(message = "审核动作不能为空")
    private String action;

    @ApiModelProperty(value = "审核不通过原因（action=reject时必填）")
    private String rejectReason;
}
```

**后端实现：**

```java
@ApiOperation(value = "执行SN绑定审核")
@PostMapping("/audit")
public ResultResp audit(@Valid @RequestBody SnBindingAuditActionReq req) {
    UserAuthUtil.isAdmin();

    UserInfo currentUser = AuthUserContext.get();
    AssertUtil.state(ObjectUtil.isNotNull(currentUser),
            new BizException("登录信息已失效，请重新登录"));

    if ("reject".equals(req.getAction())) {
        AssertUtil.state(StrUtil.isNotBlank(req.getRejectReason()),
                new BizException("审核不通过原因不能为空"));
        snBindingAuditService.reject(req.getId(), req.getRejectReason(), currentUser.getUserId());
    } else if ("pass".equals(req.getAction())) {
        snBindingAuditService.approve(req.getId(), currentUser.getUserId());
    } else {
        throw new BizException("无效的审核动作，仅支持 pass 或 reject");
    }

    return new ResultResp(1, null, "操作成功");
}
```

## 5. 核心业务逻辑设计

### 5.1 Service 层接口设计

```java
// com.yf.platform.ucenter.service.SnBindingAuditService
public interface SnBindingAuditService {

    /** 用户提交SN绑定申诉 */
    void apply(SnBindingAuditDo auditDo);

    /** 审核不通过 */
    void reject(Long auditId, String rejectReason, Integer auditorId);

    /** 审核通过（含解绑+重绑事务） */
    void approve(Long auditId, Integer auditorId);

    /** 查询用户申诉状态 */
    SnBindingAuditStatusResp queryStatus(Integer userId, String snCode);

    /** 管理端分页查询审核列表 */
    CommonPage<SnBindingAuditVo> pageList(SnBindingAuditPageReq req);

    /** 管理端查询审核详情（含关联绑定记录） */
    SnBindingAuditDetailResp getDetail(Long id);
}
```

### 5.2 申诉提交流程

```
SnBindingAuditServiceImpl.apply(auditDo)
  │
  ├─ 1. 幂等校验：同一用户同一 SN 已有 status=0 的记录 → 拒绝
  │
  ├─ 2. 调用 MES 系统获取产品 SAP ID
  │     snFacade.querySnMainBySnList(new SN(snCode))
  │
  ├─ 3. 调用 GOMS 系统获取产品名称
  │     snFacade.findBySapId(productSapId, new SN(snCode))
  │
  ├─ 4. 设置产品名称到 auditDo.productName
  │     (若 GOMS 返回为空则用 TinecoPathConfig.defaultProductName)
  │
  └─ 5. INSERT INTO java_goods.gdb_merchant_sn_binding_audit
        (user_id, user_mobile, sn_code, product_name,
         sn_photo_urls, receipt_photo_urls, status, apply_time)
```

> **幂等性：** 同一个用户对同一个 SN 码，如果已有「待审核」状态记录，返回"已有审核中的申诉，请勿重复提交"。

### 5.3 审核不通过流程

```
SnBindingAuditServiceImpl.reject(auditId, rejectReason, auditorId)
  │
  ├─ 1. 查询审核记录，校验 status = 0（待审核）
  │
  └─ 2. UPDATE java_goods.gdb_merchant_sn_binding_audit
        SET status = 2, reject_reason = ?, audit_time = NOW(), auditor_id = ?
        WHERE id = ? AND status = 0
```

> 更新行数为 0 时抛异常 "审核操作失败，记录状态可能已变更"。

### 5.4 审核通过流程（核心事务）

审核通过流程**不会自动解绑原绑定用户**。若 SN 码已有其他用户的有效绑定，审核通过操作会被拦截。

```java
@Transactional(
    transactionManager = "ucenterTransactionManager",
    rollbackFor = Exception.class,
    propagation = Propagation.REQUIRES_NEW
)
@Override
public void approve(Long auditId, Integer auditorId) {
    
    // Step 1: 查询审核记录并校验状态
    SnBindingAuditDo auditDo = snBindingAuditMapper.selectById(auditId);
    AssertUtil.state(ObjectUtil.isNotNull(auditDo), new BizException("审核记录不存在"));
    AssertUtil.state(auditDo.getStatus() == 0, new BizException("该记录已审核"));
    
    String snCode = auditDo.getSnCode();
    Integer applyUserId = auditDo.getUserId();
    
    // Step 2: 获取分布式锁
    String lockKey = StrUtil.format("product_register:sn_code_{}", snCode);
    RLock rLock = redissonClient.getLock(lockKey);
    try {
        if (!rLock.tryLock()) {
            throw new BizException("当前SN码正在被操作，请稍后重试");
        }
        
        // Step 3: 查询现有有效绑定
        UserProductRegisterDto existingBind = userBindMapper.getValidBySnCode(snCode);
        
        // Step 4: 若有其他用户的有效绑定，拦截
        if (ObjectUtil.isNotNull(existingBind)
                && !existingBind.getUserId().equals(applyUserId)) {
            throw new BizException(
                "该SN码当前由其他用户（手机号：" + existingBind.getUserMobile()
                + "）绑定，请先手动解绑后再审核通过");
        }
        
        // Step 5: MES 获取 SN 主数据
        MesSnResponse.MesSnData mesData = snFacade.querySnMainBySnList(new SN(snCode));
        String productSapId = mesData.getSapId();
        
        // Step 6: GOMS 获取产品信息
        GomsProductResponse.GomsProductSnData gomsData = snFacade.findBySapId(productSapId, new SN(snCode));
        
        // Step 7: 校验产品条件
        if (isInvalidField(gomsData.getBusinessType(), "国内")
                || isInvalidField(gomsData.getBrandCn(), "添可")
                || isInvalidField(gomsData.getProductCategory(), "大货")) {
            throw new BizException("该产品不符合注册条件");
        }
        
        String productName = StringUtils.isBlank(gomsData.getProductName())
                ? TinecoPathConfig.defaultProductName : gomsData.getProductName();
        String productPicture = StringUtils.isBlank(gomsData.getProductPicture())
                ? TinecoPathConfig.defaultProductPicture : gomsData.getProductPicture();
        
        // Step 8: ESB 获取订单信息
        SNOrderDTO snOrderDTO = snFacade.getStockRecords4Sns(new SN(snCode));
        
        // Step 9: 查询申请人历史绑定
        UserProductRegisterDto userExistingBind =
                userBindMapper.getByUserIdAndSnCode(applyUserId, snCode);
        
        if (ObjectUtil.isNotNull(userExistingBind)) {
            // 有历史解绑 → 重新激活
            userBindMapper.updateReBindProduct(userExistingBind.getId(), null);
        } else {
            // 无历史记录 → 新建绑定
            UserProductRegisterDo newBind = new UserProductRegisterDo();
            newBind.setUserId(applyUserId);
            newBind.setUserMobile(auditDo.getUserMobile());
            newBind.setSnCode(snCode);
            newBind.setProductName(productName);
            newBind.setMerchantCode(productSapId);
            newBind.setOrderReceiverContact(snOrderDTO.getOrderReceiverContact());
            newBind.setTailOrderFrom(snOrderDTO.getTailOrderFrom());
            newBind.setOrderCreateTime(snOrderDTO.getOrderCreateTime());
            userBindMapper.insert(newBind);
        }
        
        // Step 10: 更新商品编码表
        MerchantCodeManagementSaveReq codeReq = new MerchantCodeManagementSaveReq();
        codeReq.setSn(snCode);
        codeReq.setMerchantCode(productSapId);
        codeReq.setGoodsImage(productPicture);
        codeReq.setGoodsName(productName);
        codeReq.setProductCategory(gomsData.getProductCategory());
        codeReq.setProductClassName(mesData.getMediumProduct());
        merchantCodeManagementService.save(codeReq);
        
        // Step 11: 更新审核状态为通过
        int rows = snBindingAuditMapper.updateAuditPass(auditId, auditorId);
        if (rows == 0) {
            throw new BizException("审核操作失败，记录状态可能已变更");
        }
        
    } finally {
        // Step 12: 释放分布式锁
        if (ObjectUtil.isNotNull(rLock) && rLock.isLocked()
                && rLock.isHeldByCurrentThread()) {
            rLock.unlock();
        }
    }
}
```

## 6. 事务与并发设计

### 6.1 事务管理

| 方法 | 事务管理器 | 传播级别 | 说明 |
|------|-----------|----------|------|
| `apply()` | 无需显式事务 | — | 单条 INSERT，无需事务 |
| `reject()` | 无需显式事务 | — | 单条 UPDATE，无需事务 |
| `approve()` | `ucenterTransactionManager` | `REQUIRES_NEW` | 多条 SQL + 外部调用，强一致性 |

### 6.2 分布式锁设计

与现有 `UserBindController.bindProduct()` 使用相同的锁 Key 格式：

```java
String lockKey = StrUtil.format("product_register:sn_code_{}", snCode);
RLock rLock = redissonClient.getLock(lockKey);
```

### 6.3 并发场景保护

| 场景 | 保护机制 |
|------|----------|
| 审核通过时，另一用户同时绑定相同 SN | Redisson 锁串行化 |
| 两个审核人同时对同一申请操作 | DB `WHERE status = 0` + Redisson 锁 |
| 同一用户对同一 SN 重复提交申诉 | 应用层幂等校验（status=0 时拒绝） |

### 7.1 关键校验规则

```java
// === 登录态校验 ===
UserInfo currentUser = AuthUserContext.get();

// 审核不通过时原因必填
AssertUtil.state(StrUtil.isNotBlank(req.getRejectReason()), new BizException("审核不通过原因不能为空"));
```
