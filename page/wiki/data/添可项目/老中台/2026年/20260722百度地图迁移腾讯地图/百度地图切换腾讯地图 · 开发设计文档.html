需求概述

项 说明
背景 门店地图能力原基于百度地图（地点搜索、门店经纬度存储）。现需切换为腾讯地图。
目标 1) 地图搜索接口支持腾讯地图；2) 存量门店百度坐标批量转换为腾讯坐标并回写。
兼容约束 前端/下游仍按百度地图返回格式解析，因此腾讯结果需转换为百度格式后再返回（不改动前端）。
控制方式 通过配置项 map_search_provider 做服务商开关，支持灰度/回退，不硬切换。

详细设计

3.1 地图搜索接口切换

  • 入口：CustomerController

    • 类映射：@RequestMapping("/v1/private/{deviceId}/{appCode}/{appVersion}/{channel}/{deviceType}/customer")

    • 方法：@RequestMapping(value = "/searchMap", method = RequestMethod.GET) → searchMap(String query, String tag, String region, String output, String ak, String city_limit) 返回 ResultResponse

  • 核心逻辑：读取 MAP_SEARCH_PROVIDER 配置值

    • tencent：调用 TencentOsUtil.searchMap(query, region) → convertToBaiduFormat(...)；结果为 null 时直接返回 FAIL。

    • 其他（含 baidu）：维持原百度逻辑（HttpClientUtils.doGet(BAIDU_MAP_API_URL)）。

  • RunController 内部入口：/searchMap（searchMap(String keyword, String region)）直接调腾讯并转百度格式，供内部工具/测试使用。

注：开关值经一次修正，由 tengxun → tencent（提交 2adc6a4a / e36401cc），配置项注释仍为 (baidu/tengxun)，需以代码常量判断值为准。

3.2 腾讯地图工具类 TencentOsUtil

方法 入参 说明 腾讯 API
translate(longitude, latitude) 百度经度、百度纬度 百度坐标→腾讯坐标，返回 "lng,lat"；失败返回 null ws/coord/v1/translate?locations={lat},{lng}&type=3&key=
searchMap(keyword, region) 关键字、城市(region) 腾讯地点搜索，返回原始 JSONObject（含 data[]）；失败返回 null ws/place/v1/search?boundary=region({region})&keyword={keyword}&key=
convertToBaiduFormat(tencentResult) 腾讯搜索结果 腾讯→百度格式字段转换，失败返回 null —

  • type=3 含义：源坐标为百度经纬度坐标系（BD-09），目标为腾讯/火星坐标系（GCJ-02）。

  • Key 来源：ConfigKeyConstant.SP_TENCENT_OS_KEY（配置值 sp_tencent_os_key），未配置或为空时直接返回 null。

  • 统一校验：HTTP 请求失败、返回体为空、status != 0 均记录日志并返回 null。

3.3 门店坐标批量转换

  • Service 层：SpStoreInfoService.translateStoreLbs()（新增接口 + 实现）

    • 全量取门店：spStoreInfoDao.findAll()

    • 逐条处理：解析 lbs（格式 "lng,lat"）→ 拆 split[0]=lng、split[1]=lat → TencentOsUtil.translate(lng, lat) → 非空则 store.setLbs(translated) 并 save

    • 统计：successCount / skipCount（无坐标或格式非法）/ failCount，返回汇总字符串

  • Controller 入口：RunController.translateStoreLbs()（/translateStoreLbs）仅做编排，调用 Service 并返回结果。

  • 重构决策：原坐标转换循环写在 RunController 中（直接持 Dao），本次下沉到 Service 层，符合项目 Controller → Service → DAO 分层规范。

风险与优化建议

  1. 全量加载内存：translateStoreLbs 用 findAll() 一次性加载全部门店，门店量大时内存与耗时风险高 → 建议分页（Pageable/Scroll）处理。

  2. 外部 API 限频：逐条同步调用腾讯坐标转换接口，无并发控制/限流/重试退避 → 建议批量接口（locations 支持多点）或加 sleep/限流。

  3. 无事务与断点续传：转换中途失败不会回滚，且重跑会重复转换已成功门店 → 建议增加"已转换标记"或按 modifyTime 增量。

  4. 开关值注释不一致：MAP_SEARCH_PROVIDER 注释写 (baidu/tengxun)，实际有效值为 tencent → 建议同步修正注释，避免误配。

  5. 坐标语义：lbs 字段统一为 "lng,lat"，腾讯返回亦为 "lng,lat"，回写一致；需确保历史数据存储格式统一，否则 split 会误判。
