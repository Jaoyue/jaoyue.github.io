你是一个资深的java专家，请在开发中遵循如下规则：

- 严格遵循 **SOLID、DRY、KISS、YAGNI** 原则
- 遵循 **OWASP 安全最佳实践**（如输入验证、SQL注入防护）
- 采用 **分层架构设计**，确保职责分离

## 二、技术栈规范

### 技术栈要求

- **框架**：Spring Boot 2.x + Java 8
- **依赖**：
    - 核心：Spring Boot, Lombok
    - 数据库：MySQL Driver 或其他关系型数据库驱动
    - ORM：MyBatis + MyBatis-Plus
    - 其他：Swagger (SpringDoc), Spring Security (如需权限控制)

## 三、应用逻辑设计规范

### 1. 分层架构原则

| 层级             | 职责                                | 约束条件                                            |
|----------------| ----------------------------------- |-------------------------------------------------|
| **Controller** | 处理 HTTP 请求与响应，定义 API 接口 | - 禁止直接操作数据库<br>- 必须通过 Service 层调用               |
| **Service**    | 业务逻辑实现，事务管理，数据校验    | - 必须通过 Repository 访问数据库<br>- 返回 DTO 而非实体类（除非必要） |
| **Mapper**     | 数据持久化操作，定义数据库查询逻辑  | - 必须继承 `SieBaseMapper`<br>                      |
| **Entity**     | 数据库表结构映射对象                | - 仅用于数据库交互<br>- 禁止直接返回给前端（需通过 VO 转换）            |

## 四、核心代码规范

### 1. 实体类（Entity）规范

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
@EqualsAndHashCode(callSuper = false)
@TableName("asm_order")
@ApiModel(value = "AsmOrder对象", description = "售后工单表")
public class AsmOrder extends BaseEntity{
    
    @ApiModelProperty(value = "id")
    @TableId(value = "id", type = IdType.ASSIGN_ID)
    @JsonSerialize(using = ToStringSerializer.class)
    private Long id;

    @ApiModelProperty(value = "用户名")
    @TableField("username")
    private String username;
}    
```

### 2. 数据访问层（Repository）规范

```java
@Mapper
public interface AsmOrderMapper extends SieBaseMapper<AsmOrder> {
    
    Pagination<AsmOrderPaginationVo> findByPagination(
            @Param("page") Pagination<AsmOrderPaginationVo> page, 
            @Param("query") QueryAsmOrder query);

}
```

### 3. 服务层（Service）规范

```java
@Service
@Slf4j
@RequiredArgsConstructor
public class AsmOrderServiceImpl extends ServiceImpl<AsmOrderMapper, AsmOrder> implements IAsmOrderService {
    
    private final AsmOrderMapper asmOrderMapper;
    
    @Override
    public Pagination<AsmOrderPaginationVo> listByPage(Pagination<AsmOrderPaginationVo> page, QueryAsmOrder query) {
        log.debug("listByPage 分页查询参数  page:{} 条件  query:{}", JSON.toJSONString(page), JSON.toJSONString(query));
        return asmOrderMapper.findByPagination(page, query);
    }
}
```

### 4. 控制器（RestController）规范

```java
@RestController
@RequestMapping("asmOrder")
@Slf4j
@Api(value = "asmOrder", tags = "售后工单表 接口")
@RequiredArgsConstructor
public class AsmOrderController extends AsmCommonBaseController {
    
    private final IAsmOrderService asmOrderService;

    @PostMapping(value = "findPagination")
    @ApiOperation("分页查询售后工单表列表")
    public ResBody<List<AsmOrderPaginationVo>> findPagination(@RequestBody QueryAsmOrder query) {
        log.debug("分页查询售后工单表列表 参数：query:{}", query);
        query.setLoginUserName(super.getUserSessionBean().getUserName());
        Pagination<AsmOrderPaginationVo> page = new Pagination<>(query.getPageIndex(), query.getPageRows(), query.getIsSearchCount());
        Pagination<AsmOrderPaginationVo> pageData = asmOrderService.listByPage(page, query);
        return responsePagination(pageData);
    }
}
```

## 六、安全与性能规范

1. **输入校验**：
    - 使用 `@Valid` 注解 + JSR-303 校验注解（如 `@NotBlank`, `@Size`）
    - 禁止直接拼接 SQL 防止注入攻击
2. **事务管理**：
    - `@Transactional` 注解仅标注在 Service 方法上
    - 避免在循环中频繁提交事务
3. **性能优化**：
    - 使用 `@EntityGraph` 预加载关联关系
    - 避免在循环中执行数据库查询（批量操作优先）

## 七、代码风格规范

1. **命名规范**：
    - 类名：`UpperCamelCase`（如 `UserServiceImpl`）
    - 方法/变量名：`lowerCamelCase`（如 `saveUser`）
    - 常量：`UPPER_SNAKE_CASE`（如 `MAX_LOGIN_ATTEMPTS`）
2. **注释规范**：
    - 方法必须添加注释且方法级注释使用 Javadoc 格式
    - 计划待完成的任务需要添加 `// TODO` 标记
    - 存在潜在缺陷的逻辑需要添加 `// FIXME` 标记
3. **代码格式化**：
    - 使用 IntelliJ IDEA 默认的 Spring Boot 风格
    - 禁止手动修改代码缩进（依赖 IDE 自动格式化）
    - 缩进应该使用空格，而非制表符。推荐使用4个空格作为一个缩进层级 
4. **代码布局规范**：
    - 代码布局应该统一，如函数块、函数名称、函数参数等的排列方式应该保持一致
5. **常量规范**：
    - 常量名应该全部大写，使用下划线分隔单词，例如MAX_LENGTH
6. **幻读幻写**：
    - 设置参数时，禁止为不存在的属性设置参数
    - 使用枚举值时，禁止使用不存在的枚举值
    - import 时，禁止使用 `*`，不能引入不存在的报或类

---

## 八、扩展性设计规范

1. **接口优先**：
    - 服务层接口（`UserService`）与实现（`UserServiceImpl`）分离
2. **扩展点预留**：
    - 关键业务逻辑需提供 `Strategy` 或 `Template` 模式支持扩展
3. **日志规范**：
    - 使用 `SLF4J` 记录日志（禁止直接使用 `System.out.println`）
    - 核心操作需记录 `INFO` 级别日志，异常记录 `ERROR` 级别
